D2R Multi 是一个安全、高性能的 *Diablo II: Resurrected* 多开管理工具。基于 **Rust + Tauri v2** 构建，通过 Windows 原生 API 实现进程级隔离与自动化管理。

---

## 工作原理

### 1. 登录凭证保存 — Windows 多用户隔离

Battle.net 客户端的登录凭证（Token、Cookie 等）天然跟随 Windows 用户配置文件存储。不同的 Windows 用户各自拥有完全独立的 Battle.net 登录态。

**本工具利用了这一特性：**

1. **创建本地用户** — 为每个多开位创建一个标准的 Windows 本地账户。
2. **跨用户启动** — 通过 Win32 API `CreateProcessWithLogonW` 以目标用户的身份启动 Battle.net。
3. **天然隔离** — Battle.net 启动后自动读取该用户自己的凭证数据，无需额外干预。

> **效果**：每个账号只需在 Battle.net 中登录一次，之后长期免登录。凭证由 Windows 用户隔离机制自动保护，互不干扰，真正做到长期记忆。

---

### 2. 为什么只支持本地账户

本工具使用 `CreateProcessWithLogonW` / `LogonUserW` 来实现"以另一个用户身份启动程序"。这些 API 基于 Windows 本地安全认证 (Local SAM)，对账户类型有严格要求：

| 账户类型 | 是否支持 | 原因 |
|---------|---------|------|
| **本地账户** | ✅ 完全支持 | 密码存储在本地 SAM 数据库，API 可直接验证 |
| **微软账户** | ❌ 不支持 | 密码由云端管理，本地 API 无法可靠验证。微软官方确认 `CreateProcessWithLogonW` 对 MSA 存在已知兼容性问题 |
| **域账户** | ❌ 不支持 | 需要域控制器 (DC) 在线完成 Kerberos 认证，家用环境不具备此条件 |

**简单来说**：Windows 的跨用户启动 API 只为本地账户设计。微软账户和域账户的认证流程与此不兼容。

---

### 3. 多开原理

D2R 默认限制同一台电脑只能运行一个游戏实例。本工具通过两个核心操作实现多开：

#### 3.1 互斥锁 (Mutex) 清理

D2R 启动时会创建一个名为 `DiabloII Check For Other Instances` 的系统级互斥锁。当第二个实例尝试启动时，检测到该锁已存在就会拒绝启动。

**本工具的做法**：在每次启动新实例前，扫描并关闭已有的 D2R 互斥锁句柄，使新实例认为自己是第一个启动的。

#### 3.2 游戏配置 (product.db) 轮转

`product.db` 是 Battle.net 用于记录游戏安装路径等配置信息的文件。与登录凭证不同，**这个文件是全局共享的**，不跟随 Windows 用户走。如果不处理，多个实例会因配置冲突而启动异常。

**本工具的启动序列**：

```
1. 备份 (Backup)   → 保存上一个账号使用的 product.db 为独立快照
2. 清除 (Clean)    → 删除当前全局的 product.db
3. 恢复 (Restore)  → 将目标账号的快照恢复到全局位置
4. 启动 (Launch)   → 以目标 Windows 用户身份启动 Battle.net
```

> 每个账号的 `product.db` 快照独立管理，切换时自动轮转，确保各实例的游戏路径配置互不干扰。

---

### 4. 工具箱 — 当自动化触达边际

自动化启动序列能处理绝大多数场景。但在复杂的 Windows 环境中，依然可能出现边际情况（如句柄被内核锁死、进程残留、权限损坏等）。为此，工具提供了一套完备的独立工具：

#### 诊断审查（启动前预检）

| 工具 | 说明 |
|------|------|
| **多用户环境评估** | 扫描 Windows 用户配置文件，检查初始化状态，侦测微软账户冲突 |
| **权限健康检查** | 校验游戏目录 ACL、战网路径可达性、沙箱就绪状态 |

#### 独立工具

| 工具 | 说明 |
|------|------|
| **互斥锁清理** | 手动扫描并关闭 D2R 实例锁句柄 |
| **进程资源管理器** | 句柄级检查器 — 浏览所有运行进程，按 D2R 过滤，强制关闭指定句柄 |
| **存档清理** | 清除孤立的 `product.db` 快照 |
| **终止战网** | 仅终止 Battle.net 进程，保留运行中的游戏实例 |
| **修复权限** | 重置游戏目录 ACL，确保所有本地用户拥有正确的访问权限 |
| **目录镜像** | 创建目录联接点 (Junction)，用于高级多开场景下的客户端隔离 |
| **强制启动** | 跳过所有安全检查，直接尝试启动（用于调试） |
| **全量重置** | 工厂重置 — 清除所有配置与快照 |

#### Windows 系统快捷入口

| 快捷方式 | 目标 |
|----------|------|
| **本地用户管理** | 打开 `lusrmgr.msc` — 管理 Windows 本地用户和组 |
| **高级用户控制** | 打开 `netplwiz` — 配置自动登录和用户级权限 |
| **切换用户** | 触发 `tsdiscon` — 快速切换到另一个 Windows 会话，用于新账户初始化 |

> 设计原则：自动化无法处理的任何边际情况，都可以通过这些工具手动解决，零门槛。

---

### 5. 数据持久化与重定向 — 解决 C 盘重置问题

在某些网吧或高度管控的环境中，C 盘（系统盘）在重启后会自动还原，导致所有配置、账号快照和 Vault 凭据丢失。

**本工具提供了工业级的解决方案：**

1.  **数据根目录重定向**：支持在非系统盘（如 D 盘）创建 `data_path.txt` 指向数据存储目录，或通过设置面板直接迁移。
2.  **引导优先级**：程序启动时按 `程序同级 data_path.txt > AppData` 的优先级自动定位数据源。
3.  **凭据迁移引擎**：由于 Windows DPAPI 加密与用户 SID 绑定，单纯的文件复制无法迁移密码。本工具内置了原子级的重加密迁移引擎，确保在跨盘符迁移时，所有账号密码依然安全且可用。
4.  **Vault 健康监控**：仪表盘实时监控凭据的解密状态，一旦检测到环境变化导致凭据失效，会立即发出预警。

## 环境要求

- Windows 10/11 (x64)
- **管理员权限**（用于创建用户和跨用户启动）
- Battle.net 必须安装在默认路径 `C:\Program Files (x86)\Battle.net`，且安装时勾选"为所有用户安装"
- 多开位必须使用 **标准本地 Windows 账户**（不支持微软账户和域账户）
